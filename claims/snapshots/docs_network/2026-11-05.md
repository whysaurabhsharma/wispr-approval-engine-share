Configure your network for Wispr Flow

                Last updated 8 days ago

Available on:
 Mac, Windows
If downloads are blocked or dictation is slow on your corporate network, check outbound access and TLS inspection. Enterprise admins can also restrict Flow to approved networks.

Fix slow dictation caused by SSL/TLS inspection
Flow respects system proxy settings and organizational root certificates, including TLS inspection, for dictation, uploads, and SSO session management. Dictation requires valid, self-signed root certificates in macOS System Roots or the Windows root store; malformed or intermediate-only corporate certificates can fail even when other connections work.
TLS inspection can slow dictation without preventing text delivery. Networks that do not intercept the connection do not need this bypass.
Use the complete wildcard destination list, including *.wisprflow.com; *.wisprflow.ai alone is insufficient, and the list must also cover alternate dictation connections and other Flow connections. Destinations can change without an app update and differ between colleagues, so testing one exact hostname is insufficient.
Important:
 TLS stays enabled. The gateway stops intercepting and re-encrypting these connections; traffic is not sent in the clear. The exception covers Flow's dictation traffic, while other TLS sessions remain subject to your inspection policy.
DLP tools that need decrypted traffic cannot inspect these endpoints. Endpoint DLP, DNS controls, egress-volume monitoring, and other controls that do not require decryption remain available.

Restrict organization access to approved networks
Firewall rules and your organization's IP allowlist are separate: allowing a hostname through your firewall does not add that network to the IP allowlist.
IP allowlist appears only for Enterprise organizations enabled by Wispr. Changing it requires an active Enterprise plan and enterprise admin permissions. It applies to Wispr's account and management services, and is not enforced on Android or on the speech-processing service.
Entries:
 Up to 64 IPv4/IPv6 CIDRs are accepted; invalid entries, empty lists, 0.0.0.0/0, and ::/0 are rejected, and each invalid entry is reported separately while valid entries are kept.
Addresses:
 Use your network's actual outgoing (egress) IP, and include expected office IPs, VPN exit IPs, and remote locations. IPv4 and IPv6 ranges match only their own address type, so dual-stack networks need both; IPv4-mapped IPv6 addresses match IPv4 ranges.
Saved ranges:
 Host addresses are converted to network addresses, and duplicates are removed, keeping first-occurrence order.
Important:
 To prevent admin lockout, Save is unavailable until Flow detects your current IP and the proposed ranges include it. If detection fails, reopen the dialog.

Restrictions apply to signed-in access, not anonymous use. If Flow cannot initially load the access rules or validate a saved list, restrictions are not applied. The editor's current-IP lookup keeps working even when other signed-in access is blocked.
If “IP allowlist (locked by Wispr)” appears, changes are disabled; contact support to unlock.
Disable the IP allowlist
Your current IP must be covered by the existing list. An empty list cannot disable the feature.
Warning:
 Disabling clears saved IP ranges; you must re-enter them to enable restrictions again.

If a user sees “Your network isn't allowed”
Flow signs Mac and Windows users out when their network is unapproved or their IP cannot be determined, including accounts added through SCIM. The message names the organization when known.
Warning:
 Blocking dismisses any in-progress dictation, prevents further dictation, and stops any in-progress Notetaker recording. You are fully signed out, not paused.

The block clears automatically the next time a request to Wispr succeeds from an approved network; if you have not manually signed out, an allowed network may sign you straight back in. A still-disallowed network returns the blocked screen.
Sign Out instead clears the blocked screen and returns to normal sign-in. If the expected network is missing, ask your admin to review IP allowlist in Settings → Organization from an allowed network.
